静态站点最迷人的地方，是它几乎不需要被「维护」。没有数据库连接，没有后台进程，也没有半夜突然报警的服务。它只是几个文件，安静地待在某个目录里。

## 先选一条最窄的路

这次我没有从框架开始。没有脚手架，没有构建步骤，只有 `index.html`、一份样式表和一个脚本文件。浏览器能直接读懂它们，GitHub Pages 也只需要把目录原样发布。

部署配置可以短到只看一眼就明白：

```yaml
name: Deploy blog
on:
  push:
    branches: [main]
permissions:
  contents: read
  pages: write
  id-token: write
```

剩下的交给官方的 Pages Action。每次推送到 `main`，站点就会重新生成。整个过程没有缓存要清，也没有依赖要锁。

## 三个约定

第一，内容与界面分开。文章放在数据文件里，页面只负责呈现。这样改写样式时，不会碰到正文；更换内容时，也不需要理解 CSS。

第二，所有交互都必须能回到一个稳定的状态。刷新页面后，当前文章、主题、筛选条件都应该还在。

第三，宁可少一个功能，也不要多一个让人分心的按钮。

## 让站点呼吸

静态不等于僵硬。适当的过渡、渐入和悬停反馈，会让页面像一张被轻轻翻动的纸。关键是克制：只在你注意到它的那一刻出现，不打断阅读。

```css
.article-enter {
  animation: rise .45s cubic-bezier(.22, 1, .36, 1) both;
}

@media (prefers-reduced-motion: reduce) {
  .article-enter { animation: none; }
}
```

最后一行很重要。会呼吸的站点，也应该懂得在有人不舒服的时候停下来。

## 发布之后

站点上线的那一刻并没有想象中隆重。它只是出现在一个很长的网址后面，背景是白的，字是黑的，甚至没有一张欢迎图。

但我知道，从那一刻起，我随时可以打开它，写下下一段话。

这已经足够了。
